# 정부지원사업 공고 자동 수집기 — 사용 가이드

기존에 `gov_program` 테이블의 공고 12건은 손으로 넣은 것이었습니다(`003_programs_seed.sql`).
이 수집기는 그 자리를 **공공 API에서 자동으로 받아온 실제 공고**로 채웁니다.

---

## 1. 명령어 세 가지

```bash
npm run collect -- --dry     # DB 없이 정규화 결과만 화면에 출력 (안전, 아무것도 안 바뀜)
npm run collect              # 목업 데이터로 DB에 적재 (연습용)
npm run collect -- --live    # 실제 공공 API 호출 (API 키 필요)
```

특정 소스만 돌리려면 이름을 붙입니다:

```bash
npm run collect -- kstartup --live
```

**처음이라면 `--dry`부터 실행해 보세요.** DB를 건드리지 않고 "어떤 공고가 어떻게 분류되는지"만 보여줍니다.

---

## 2. 실제 데이터 — OneGov (API 키 불필요, 권장)

`onegov` 소스는 **인증이 필요 없어 지금 바로** 실데이터를 받을 수 있습니다.

```bash
npm run collect -- onegov --live
```

[OneGov](https://korea-onegov.vercel.app)는 K-Startup·기업마당 등을 이미 수집·정규화해 둔
공개 API입니다. 우리는 그 위에서 매칭에 필요한 항목만 다시 뽑아냅니다.
`detail_url`은 원 포털을 그대로 가리키므로 사용자를 원본 공고로 보내는 데 문제가 없습니다.

> **중요 — 조달 입찰공고 걸러내기**
> OneGov의 `category=grant`는 이름과 달리 나라장터(g2b) 입찰공고를 함께 담습니다.
> 실측 결과 200건 중 157건(78.5%)이 "리모델링공사", "차량 임차용역" 같은 조달 건이었습니다.
> 그래서 출처가 `bizinfo.go.kr` / `k-startup.go.kr` 인 것만 통과시킵니다
> (`ingestion_source.config.allowHosts`). 이 필터를 지우면 쓰레기 공고가 쏟아집니다.

---

## 2-1. 공공 API 직접 호출 (선택)

`kstartup` · `bizinfo` 소스는 공공데이터포털 키가 있어야 동작합니다.

1. [공공데이터포털](https://www.data.go.kr) 회원가입
2. 아래 두 API에 활용신청 (보통 자동승인, 1~2시간 내 발급)
   - `창업진흥원_K-Startup 사업공고 정보`
   - `중소벤처기업부_기업마당 지원사업 정보`
3. 발급받은 **일반 인증키(Decoding)** 를 `.env`에 추가

```
DATA_GO_KR_API_KEY=발급받은키
```

4. 실행

```bash
npm run collect -- --live
```

> 키가 없거나 비어 있으면 자동으로 목업 모드로 내려갑니다. 빈손으로 실패하지 않습니다.

## 3. 무엇이 자동으로 채워지나

공고 제목과 본문을 읽어 매칭 엔진이 쓰는 항목들을 추론합니다.

| 항목 | 예시 | 판단 근거 |
|---|---|---|
| `target_stages` | 예비, 1-3년 | "창업 3년 이내", "예비창업자" 같은 표현 |
| `target_segments` | PRE, YOUTH, WOMAN | "만 39세 이하", "여성", "소상공인" 등 |
| `max_amount` | 100000000 | "최대 1억원", "5,000만원" 등 금액 표기 |
| `region` | 서울 | 지역 필드 우선, 없으면 본문에서 |
| `funding_type` | 사업화 / 융자 / 보증 / R&D | **제목 우선**으로 판정 |
| `period_end` | 2026-03-31 | 접수 마감일 |

> **제목 우선**이 중요한 이유: 사업화 지원사업은 본문에 "멘토링·교육"을 거의 항상 언급합니다.
> 본문만 보면 전부 "컨설팅"으로 분류되어 버려서, 제목의 핵심 키워드를 먼저 봅니다.

### 매칭 탈락 방지 보정

`server.js:401`은 **업력과 세그먼트가 모두 비면 공고를 매칭에서 탈락**시킵니다.

```js
if (segOverlap.length === 0 && !stageMatch) return { hardPass: false };
```

그런데 지자체 공고는 "참여기업 모집"으로만 적혀 있어 둘 다 안 잡히는 경우가 흔합니다
(실측 35건 중 24건). 그대로 두면 **수집해도 사용자에게 영원히 안 보입니다.**

그래서 '사업자 대상'이 분명하면 운영 중인 사업자 전 구간을 기본값으로 채웁니다.
예비창업자는 넣지 않습니다 — 사업자등록이 없으면 '참여기업'이 될 수 없기 때문입니다.

보정 후 실측(35건 기준):

| 프로필 | 하드필터 통과 |
|---|---|
| 예비창업자 | 3건 |
| 소상공인(2023년 설립) | 31건 |
| 청년창업 1년차 | 25건 |

예비창업자 통과가 적은 것은 **버그가 아니라 정확한 동작**입니다. 지자체 기업지원사업은
대부분 사업자등록을 요구합니다. 예비창업자용 공고가 필요하면 `kstartup` 소스를 쓰세요.

## 4. 기존 데이터는 안전한가

네. 손으로 넣은 12건과 수집분은 `auto_ingested` 값으로 구분됩니다.

```sql
-- 손으로 넣은 기존 12건
SELECT * FROM gov_program WHERE auto_ingested = FALSE;

-- 자동 수집분만
SELECT * FROM gov_program WHERE auto_ingested = TRUE;

-- 자동 수집분만 전부 지우기 (기존 12건은 남음)
DELETE FROM gov_program WHERE auto_ingested = TRUE;
```

## 5. 수집 이력 확인

```sql
SELECT source_id, started_at, status, fetched_count, upsert_count, error_count
  FROM ingestion_run ORDER BY started_at DESC LIMIT 10;
```

`status` 값의 뜻: `success` 전부 성공 / `partial` 일부 실패 / `failed` 실패

## 7. 파일이 어디 있나

```
migrations/007_ingestion.sql        DB 구조 (테이블·컬럼 추가)
scripts/run-collector.js            실행 스크립트
src/collectors/
  ├─ base/http-client.js            타임아웃·재시도·유량제한
  ├─ base/rate-limiter.js
  ├─ normalize/korean.js            ★ 한국어 분류 규칙 (분류가 틀리면 여기를 고침)
  ├─ runner.js                      전체 조율
  ├─ kstartup/                      K-Startup 수집기
  └─ bizinfo/                       기업마당 수집기
```

**분류가 마음에 안 들면 `src/collectors/normalize/korean.js` 한 파일만 고치면 됩니다.**
수집기가 몇 개든 분류 규칙은 여기 한 곳에 모여 있습니다.

---

## 8. 소스를 추가하려면

`src/collectors/<이름>/index.js`에 함수 두 개만 만들면 됩니다.

```js
module.exports = {
  fetchPage,   // ({ client, config, apiKey, page, pageSize }) => { rows, hasMore }
  normalize,   // (원문 1건) => gov_program 행 또는 null
};
```

그리고 `ingestion_source`에 같은 이름으로 한 줄 넣으면 러너가 자동으로 인식합니다.
러너 코드는 건드릴 필요가 없습니다.
